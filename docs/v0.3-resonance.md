# Lilies in the box v0.3「共鸣」

## 闭环

v0.3 的本地闭环是：现实事项进入任务/日历/信笺，莉莉丝在明确会话中陪伴，完成结果进入不可变成长账本，再确定性解锁服装、姿态和盒中陈设。共鸣从不改变权限、隐私或外部连接档位。

## 桌宠与桌面

- `WinEventHub` 统一转发前台、位置、显示、隐藏、最小化与销毁事件；原生回调不直接操作 QML。
- `PetHabitatController` 在前台窗口稳定后选择上沿或屏幕边缘栖息点，手动拖动会让本次窗口脱离吸附。
- 角色采用分层 QML：身体、发梢、肩胸、裙摆、裂光和阴影以不同相位呼吸；红绳使用 14 节点约束并分别绑定人物与盒子。
- `WindowCatalogService` 按 AUMID/规范化可执行身份分组，维护 MRU、最小化、显示器与原生图标缓存；Dock 的缩略架和“全部窗口”使用不同展开逻辑。
- 敏感、会议、远程桌面与 UAC 进入 `BLOCKED`；全屏游戏进入 `SILENT`。这两类状态都会移除桌宠热区和主动气泡。

## 工作与成长

- 任务、循环实例、专注、论文阅读和提醒由 SQLite 确定性服务管理，不依赖模型。
- 专注期间同一娱乐上下文稳定 45 秒后提醒一次，新停留仍受 10 分钟冷却；全屏游戏只投递 Windows 通知。
- 共鸣规则和每日上限由 `GrowthEngine` 的追加事件计算；重复来源使用幂等键，重开任务写补偿事件，不删除账本。
- 五阶段为初遇、熟悉、信赖、亲近、相伴；状态页精确显示当前值、下一阈值与解锁来源。

默认积分是确定性的：任务实例 `+10`；每 25 分钟有效专注 `+8`、每日最多 4 次；每 20 分钟论文阅读 `+6`、每日最多 3 次；一次 Slack 整理 `+5`、每日最多 3 次；重复积分每日总上限 60。主动休息不加减分，但完成 3 次会解锁休息内容。阶段区间为初遇 0–99、熟悉 100–299、信赖 300–699、亲近 700–1199、相伴 1200 以上。

v0.3 声明 6 套服装：初遇裂纹裙、清凉棉质连衣裙、家居开衫、阅读罩衫、专注外套、休息睡裙；8 个姿态：抱拳祈祷、窗口栖息、屏幕边缘探身、倾听、论文阅读、展示说明、红绳托盒、休息。姿态与服装按兼容表组合，不制造无意义的全排列。

## Calendar 与 Slack

连接器默认关闭，配置与 OAuth 只能由用户在独立可聚焦窗口发起。

- 四个轴独立保存：信息范围、打扰方式、本地留存、协助能力。
- Google 使用系统浏览器、随机 IPv4 loopback、PKCE S256 和 state；默认只读，确认执行档才请求 owned-events 写权限。
- Calendar 使用前 1 天/后 30 天滚动窗口、同步 token、ETag 与 410 全量重置；写入只允许受限事件字段，不删除事件或批量修改循环系列。
- Slack 使用个人 custom app、User Events 与 Socket Mode。Socket envelope 先 ACK，再过滤、去重和入库；`app_mention` 不会冒充“本人被提及”。
- 元数据档不保存正文；可搜索摘要只保存加密的有界摘要；扩展缓存保存选中来源并按 30 天清理。降档会立即删除密文或重写为有界摘要，不保留隐藏正文。
- Calendar/Slack 正文不进入通用模型工具结果。只有用户点选当前单项并主动要求总结、拟稿或解释时，才进入隔离协助流程。
- 所有写操作先创建不可变 `ActionProposal`。UI 展示目标、修改前后、来源版本和过期时间；Slack 编辑会作废旧提案并生成新预览。确认 UI 是唯一提交入口。

OAuth、Slack xapp 与访问/刷新令牌只进入 Windows Credential Manager。正文/摘要密文的 AES-GCM 主密钥也只存凭据管理器；安全存储不可用时连接器关闭，不回退为明文。

### 实际连接与同步

- Calendar 使用用户自己的 Google Desktop OAuth Client；连接、启动和系统唤醒后立即刷新，之后每 10–15 分钟抖动轮询。到期提醒由本地调度器完成，不会每分钟访问 Google；本地提醒表只保存“日程即将开始”这类泛化标题。
- Calendar 只创建事件、修改非循环事件或单个循环实例；不删除事件、不批量修改循环系列。确认前会复核 ETag，远端已变化时旧预览作废并要求重新确认。
- Slack 使用用户自己的 personal custom app、Socket Mode 与 User Events。精选频道是本地过滤：Slack 会先投递 scope 覆盖的事件，未选择来源随即在本机丢弃。确认执行只向原频道、私信或原线程发送新回复，不编辑、删除、上传或读取附件。
- “清除本地内容”会删除正文、摘要、协助句柄、未决预览和 Calendar 派生提醒，但保留账号凭据与配置；“断开账号”还会停止同步/Socket Mode，并删除 OAuth、xapp、可选签名密钥和缓存。两者都不会删除远端日程或 Slack 消息。
- 从扩展缓存降为可搜索摘要会直接把密文重写成有界摘要；降为元数据会删除密文。连接器组件审计只保留事件/提案 ID、字段名、状态和长度，不复制日程标题、外部正文或回复正文。

## 模型与权限

模型优先级为明确对话/回复、论文划词、用户触发的 Calendar/Slack 协助、主动内容、屏幕理解、记忆归档。每个模型同一时刻只运行一个任务，前台上下文变化会取消过期低优先级任务。

v0.3 不公开 `growth.grant`、解锁授予、OAuth/Slack 原始 API、Token 读取、Calendar/Slack 直接提交或任意 Shell。外部内容和历史文本均按不可信数据处理。

## 数据位置

项目创建的数据库、连接器元数据、加密内容、缓存、截图和运行状态只写入：

```text
F:\code\Lilies in the box\private-data
```

F 盘不可用时进入受限恢复模式，不静默回写 C 盘。Windows Credential Manager 是唯一由系统托管的例外。
